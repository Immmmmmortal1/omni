# omniar.deepseek-scene-line

- status: approved
- type: feature
- sub-gate: api-contract (external LLM) + secret handling

## Intent

After the user taps an object and a face is pinned (world-locked), speak one short,
context-appropriate line as if the OBJECT itself is talking. The line is generated by
DeepSeek from the pinned object plus other objects visible in the scene. It shows as a
speech bubble anchored above the face in the AR scene.

## Product decisions (confirmed with user)

- Display: AR speech bubble above the pinned face (follows the face on screen).
- Persona: object first-person, playful/anthropomorphic.
- Language: follow the device/system language.
- Context sent to model: the selected object label + other detected object labels in the frame.
- Failure fallback: show a local preset line (never block or crash).
- API key storage: gitignored `Secrets.xcconfig` injected into Info.plist (never in source / never committed).
- Trigger: generate once per pin. Clearing (tap empty / Esc) removes the bubble.

## API contract

- API contract source: DeepSeek official docs (api-docs.deepseek.com) + 2026 migration notes.
- Endpoint: `POST https://api.deepseek.com/chat/completions`
- Method: POST
- Request fields:
  - `model`: string — `deepseek-v4-flash` (default) or `deepseek-v4-pro`.
  - `messages`: array of `{role: system|user, content}`.
  - `temperature`: number (~1.3 for creative chat).
  - `max_tokens`: int (small, <= 60 — one short line).
  - `stream`: false.
- Response fields:
  - `choices[0].message.content`: string — the line to display (consumed).
  - `choices[0].finish_reason`: string — used only to detect truncation.
  - `usage`: ignored.
- Headers: `Authorization: Bearer <key>`, `Content-Type: application/json`.
- Error/empty states: 401 invalid key, 429 rate limit, network failure, empty content,
  key not configured. All map to local fallback line.
- Refresh/retry requirement: single attempt per pin, 8s timeout; on failure use fallback
  (no auto-retry).

## Business mapping table

| API field | Meaning | Business state | UI owner | Expected behavior | Validation case |
| --- | --- | --- | --- | --- | --- |
| choices[0].message.content | Generated line | `speech.text` | SpeechBubbleView | Bubble shows the line above face | normal-success |
| choices[0].finish_reason | stop/length | truncation flag | (internal) | length -> still show partial | truncated |
| (transport) HTTP status/error | success/fail | fallback trigger | SpeechBubbleView | Show local preset line | 401/429/offline |
| Info.plist DEEPSEEK_API_KEY | configured key | client enabled? | (internal) | empty/placeholder -> fallback only | no-key |

## Unused fields

- `usage.*`, `id`, `object`, `created`, `reasoning_content` — not needed for one-line UX.

## Golden cases

- Case: normal success
  - Input: selected="cup", others=["dining table","laptop"], key set
  - Expected business: speech.text = model content (non-empty, first-person)
  - Expected UI: bubble above cup face
- Case: empty content -> fallback line
- Case: 401 invalid key -> fallback line
- Case: 429 rate limit -> fallback line
- Case: offline / timeout -> fallback line
- Case: no key configured -> fallback line only (no network call)
- Case: clear (tap empty / Esc) -> bubble removed

## Contract validation

- On-device manual run through the golden cases. Without a key, the no-key + fallback
  path is verifiable now; the live-success + HTTP-error paths are verified once the user
  provides the key. Remaining manual self-test: normal-success, 401, 429 with real key.
